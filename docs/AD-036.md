# Resumable literature review stages

Tracking: [AD-036 / issue 6](https://github.com/hashimkarim/agentic-literature-review/issues/6).
Converted the existing project draft in place; item

## Existing contracts

`WorkflowEngine` already runs relevance, metadata, key findings, comparison and
synthesis. The repository stores typed proposals and explicit review decisions;
synthesis uses an accepted comparison and has its own acceptance path. Q&A
already distinguishes literal passage validation from model support review.
Run JSON/events persist, but multi-stage recovery and uncertain in-flight
operations are not yet reconciled. Browser disconnect does not own execution.

## Delivery order

1. Scope-bound search/passage operations: freeze selected paper revisions,
   recheck current project access and revision on every read, return canonical
   passage identities, never infer support from citation existence.
2. Durable review checkpoints referencing existing workflow runs/proposals.
   Record intent before dispatch; recover finished results, preserve accepted
   stages, and pause uncertain interrupted work instead of silently replaying.
3. Compose screening, extraction, comparison and synthesis using existing
   proposal/review contracts. No generated canonical library writes. Validate
   accessible sources again before review/acceptance.
4. HTTP/UI resume and review controls, deterministic restart/disconnect/failure
   fixtures, then native T3 synthetic acceptance checks.

Tool-enabled requests must fail before execution when selected discovery says
`tools=false`. The selected Codex route is text-only; no account/model fallback
is allowed. Tool-enabled execution uses deterministic SDK fixtures until a
capable route is separately qualified. Do not introduce a provider runtime,
change authentication or migrate the registry SDK pin for this work.

## Remaining acceptance gates

- [ ] Resume without repeating accepted paper processing, including restart in
      the dispatch/result-persistence window.
- [ ] Scope/revision/existence checks and evidence-support decisions remain
      separate; revoked or stale passages cannot be displayed as current proof.
- [ ] Metadata/relevance/synthesis remain proposals with provenance and explicit
      acceptance/rejection; resume preserves these decisions.
- [ ] Unsupported tool requests make zero provider calls; supported fixtures
      exercise app-owned retrieval through the supported SDK interface.
- [ ] Native browser checks against disposable research data; no real source or
      manuscript mutation and no live tool-capability claim for Codex.
